# Phase 28.7 Plan 06: Wave B.3 — Per-Runtime Converters (codebuddy + cline) Summary

## TL;DR

Wave B.3 ships **2** per-runtime SKILL.md converters: **codebuddy** (uniform skills-dir layout) and **cline** (SPECIAL CASE per D-09 — rule-block embedding into `.clinerules`, not a `skills/` directory). Total: **10 of 13** converters now in tree (cumulative with Waves B.1 + B.2). **Hermes is intentionally absent per D-10** — a dedicated test guards `scripts/lib/install/converters/hermes.cjs` non-existence so future plans cannot drift hermes back into scope without a deliberate D-10 amendment. cline.cjs is the first converter with a non-uniform export surface (it exports `convert` + `buildClinerulesFile`); the installer (Plan 28.7-08) will detect `layout.specialCase === 'clinerules-embed'` and route accordingly. **26 node:test cases pass; Waves 1 + 2 still pass (111/111); no regressions.**

## Tasks executed

### Task 1: Implement codebuddy.cjs + cline.cjs

- **codebuddy.cjs** (55 LOC) — Claude-compatible passthrough; runtime tag `'codebuddy'`, adapter display `'CodeBuddy'`. Mirrors cursor/windsurf/trae/qwen structure: `extractFrontmatterAndBody` → `buildFrontmatter('gdd-')` → `rewriteSlashRefs('codebuddy')` → `ensureAdapterHeader('CodeBuddy')`. No tool-name rewrite needed (CodeBuddy accepts Claude vocabulary natively).

- **cline.cjs** (206 LOC) — SPECIAL CASE per D-09. Exports TWO functions:
  - `convert(content, skillName, opts) → string` returns a markdown FRAGMENT (rule-block) of shape `## gdd-<name>\n\n<description>\n\n<body>\n`. NO YAML frontmatter, NO `<!-- gdd: ... adapter -->` HTML comment, NO `name:` field — the heading IS the identifier in cline's rule-block model. Description is extracted via a single-line regex over the source frontmatter; skillName is normalized to strip prior `gdd-`/`gsd-` prefix.
  - `buildClinerulesFile(skillBlocks) → string` assembles the final `.clinerules` content from an array of `{name, block}` entries. Prepends a 4-line header (`# get-design-done rules\n\n<!-- Auto-generated... -->\n\n`), joins blocks with `\n\n`, ends with `\n`. Defensive for null/undefined/empty-array input → header-only file.

  Both functions are pure (no fs/env/path). The installer (Plan 28.7-08) owns the disk write to `<cline-config>/.clinerules`.

## Decisions Made

- **Cline two-export shape:** `convert` returns a fragment (rule-block), `buildClinerulesFile` aggregates. Rationale: cline's storage model is a single concatenated file (`.clinerules`), so the converter cluster needs an aggregator step. Pattern is locked by the plan's `<interfaces>` block and tested by 6 dedicated buildClinerulesFile tests.
- **Block format (markdown-only):** `## gdd-<name>\n\n<description>\n\n<body>\n`. No YAML frontmatter, no HTML comment, no `name:` field. The heading IS the identifier in cline's rule-block model. Test `cline convert does NOT emit YAML frontmatter` and `cline convert does NOT emit adapter HTML comment` lock this contract.
- **File header (`# get-design-done rules`):** 4-line provenance preamble at the top of `.clinerules` so anyone reading the generated file knows it is auto-generated and the authoritative source is upstream SKILL.md files.
- **Skill-name normalization:** strip `gdd-`/`gsd-` prefix on input to `cline.convert` to prevent `## gdd-gdd-foo` from `cline.convert(src, 'gdd-foo')`. Mirrors `shared.buildFrontmatter`'s behavior; verified by explicit tests with both prefixes.
- **Description extraction (single-line regex):** SKILL.md descriptions are always single-line strings in the GDD source set; full YAML parse is unnecessary overhead. Regex tolerates leading whitespace, surrounding quotes, and CRLF endings.
- **D-10 enforced by test, not just NOTICE comment:** `fs.existsSync('scripts/lib/install/converters/hermes.cjs') === false`. If hermes ever drifts back into the converter directory, the test fails and forces a deliberate D-10 reconsideration.
- **Defensive null/undefined for buildClinerulesFile:** returns header-only file rather than throwing. Useful for installer dry-run paths in Plan 28.7-08. Two tests cover the defensive paths.
